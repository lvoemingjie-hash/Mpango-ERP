feat: Implement Identity & Security Layer with JWT auth and RBAC

## Summary
Complete implementation of authentication and authorization for Mpango ERP backend,
providing JWT-based multi-tenant authentication and role-based access control.

## Features Added

### Authentication (JWT)
- JWT token generation with HS256 algorithm
- Access tokens (30min) and refresh tokens (7 days)
- Token validation middleware with proper error codes
- Multi-tenant login flow (tenant_code + email + password)
- Token refresh endpoint preserving tenant context
- /auth/me endpoint returning user info with roles/permissions
- Bcrypt password hashing with salt

### Authorization (RBAC)
- Permission-based access control per rbac_matrix.md
- RequirePermission middleware for endpoint protection
- Admin role bypass (has all permissions)
- Permission format: `<resource>:<action>` (e.g., users:read, orders:create)
- All 13 protected endpoints now enforce permissions

### Tenant Security
- Tenant schema derived ONLY from JWT claims (never headers/params)
- Prevents tenant isolation bypass attacks
- Database search_path set from JWT token
- Tenant resolver integrated with auth middleware

### Core Security Module
- `backend/core/security.py`: JWT and password utilities
- Custom exceptions: InvalidTokenError, ExpiredTokenError
- Token payload: user_id, tenant_id, tenant_schema, exp, type

### Middleware
- `backend/api/middleware/auth.py`: JWTBearer for token validation
- `backend/api/middleware/rbac.py`: RequirePermission for authorization
- Updated `backend/api/dependencies.py`: Tenant resolver from JWT

### CRUD Operations
- `backend/crud/wholesaler.py`: Tenant lookup by code
- `backend/crud/user.py`: User queries with eager-loaded permissions

### Updated Endpoints
- `backend/api/v1/auth.py`: Full implementation (login, refresh, me, logout)
- `backend/api/v1/users.py`: Added RBAC dependencies
- `backend/api/v1/roles.py`: Added RBAC dependencies
- `backend/api/v1/orders.py`: Added RBAC dependencies
