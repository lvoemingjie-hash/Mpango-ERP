# 收款精度与会话代际有限修复

本文件是实现合同，不是独立安全、完整财务或发布验收。候选身份、
逐次结果、首败、恢复摘要及最终停止状态以本任务外部交付原件为准。

## 收款合同

唯一权威为订单已经保存的 currency_snapshot：KES 两位、UGX 整数；
允许数值等价尾零，不接受通过舍入、截断、浮点转换得到的替代金额。
CanonicalPaymentService 的公共入口最终进入锁内入口，后者在任何
payment/receipt/hold/ledger/binding/order 经济写入之前验证币种及精度。
复用现有 money 规则；非法精度返回 PAYMENT_AMOUNT_PRECISION。

未知币种禁止新财务写入，返回 PAYMENT_CURRENCY_UNVERIFIED；只有原有
严格同键、同请求、同订单及客户归属的历史零写入重放可原样返回。
已知币种的共享服务重放仍检查精度。无公共 bypass 参数，不改锁序、
保存点、收据、付款申报内核或历史金额。head044 自身禁止落库 USD，
其负控只在已持锁 ORM 对象的不落库来源上测量，未禁用数据库约束。

新增验证分层：真实 JWT/HTTP 的新付款拒绝、共享锁内入口、受控既存
UGX 小数申报确认、合法部分/最终及重放、归属拒绝、写后故障完整回滚。
受控改写已付款订单币种或付款客户后的 HTTP 热缓存不等于共享服务
重放：原始观察保留，本轮不改缓存。不能据服务级拒绝宣称热缓存也
重新验证了数据库历史；不能把人工腐败历史描述为合法产品操作。

## 会话合同

会话代际只存在于 live store，不进入持久化身份 DTO。登录、零售商
登录、退出、pending identity 与工作区切换均使旧代际失效；同一用户
及相同 token 的重新登录仍是新代际。每个请求在发出时绑定所属代际。
刷新、排队、重试、权限复核、toast、logout、redirect 及 finally 都
只作用于所属代际；旧队列在边界事件立即拒绝。旧 finally 不能清理
新代际刷新；同代际延迟401可复用同伴已刷新的 token，最多重试一次。

显式 Authorization（含空值/各种大小写）在重试时仍保留；公共
skipAuthInterceptors 请求不触发会话副作用。客户端拒绝过期响应并不
撤销服务器已经完成的操作，不承诺跨标签页/跨设备 SSO 或后端隔离新增。

## R03：队列最小后续方案（仅设计）

- 单实例内区分 accepting 与 consuming：停止首先拒绝新入队，不立刻
  退出 worker；已接收项在部署宽限期内排空，超时项进入明确失败终态。
- 仅覆盖当前已承诺异步导出类型。启动时对这些类型的旧 pending/running
  作受控认领/判定，无法安全重放则记中断失败并提示重新发起；不盲目
  重放有副作用任务，不承诺 exactly-once。
- 只核销已登记的任务输出；不按路径前缀扫删，不删除其他 worker 数据。
  已完成文件继续遵循原下载权限，不因队列终止扩大可见范围。
- 最小接触面为既有 local_queue、main 的生命周期接线、导出任务及
  既有 job 状态持久化；若现存状态不足才另提精确字段申请，不引 Celery。
- 未来用事件屏障验证：忙碌worker+排队项排空、超时显式失败、停止后
  入队拒绝、重启后无永挂、原成功任务不重复执行。具体宽限期与HTTP
  拒绝码交 CTO 定；本轮未修改队列、未运行停机或重启实验。

本候选不复用旧工具绿灯为新产品验收，不改 verify-reuse/CI 选集或
工作流。旧员工问题和 hosted 容量继续由原 CI 线处理，远端写与发布
操作均未授权。完整收入确认、退款及多实例任务可靠性仍为既有边界。
