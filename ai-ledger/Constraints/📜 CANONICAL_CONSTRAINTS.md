📜 CANONICAL_CONSTRAINTS.md

Mpango ERP — Non-Negotiable Engineering Constraints
Status: 🔒 FROZEN
Owner: CTO
Scope: Applies to ALL code, APIs, migrations, views, jobs, and AI-generated output.

0. Authority

These constraints are absolute.

Any code, schema, API, or design that violates ANY rule in this document is INVALID, even if:

it “works”

it passes tests

it looks reasonable

it was generated by an AI

Violations must be fixed. No exceptions without explicit CTO approval.

1. Multi-Tenant Isolation (P0)
MUST

All data access MUST be scoped by tenant at the Service / DB session layer.

tenant_id MUST be injected from the authenticated token/context.

Database queries MUST execute under the correct tenant schema (SET search_path TO t_*).

MUST NOT

Accept tenant_id, tenant_schema, or tenant identifiers from request payloads, query params, or headers.

Query tenant data from the public schema (except tenant registry metadata).

Allow any reporting or business API to run without tenant enforcement.

2. Ledger & Accounting Integrity (P0)
MUST

Ledger is append-only.
No UPDATE or DELETE on ledger_entries.

Every transaction MUST satisfy:

SUM(amount) = 0


All financial state (balances, AR, cash) MUST be derived from the ledger, never stored as mutable fields.

MUST NOT

Store “current balance” columns.

Recompute ledger data in Python that can be aggregated in SQL.

3. Reporting & BI Semantics (P0)
MUST

All reporting objects MUST:

Be named with prefix rpt_* or mv_*

Live in the tenant schema

Be read-only

All read models MUST expose:

reporting_currency_code CHAR(3) NOT NULL


All reporting time axes MUST use:

transaction_date

MUST NOT

Use created_at in reporting filters, GROUP BY, or charts.

Expose raw transactional tables (ledger_entries, orders, etc.) directly to dashboards or exports.

Use FLOAT for monetary values.

4. API Contract Discipline (P0)
MUST

APIs MUST conform to the approved API Contract.

Input and output MUST be explicitly defined via Pydantic schemas.

All filtering and aggregation MUST be validated and whitelisted.

MUST NOT

Accept dynamic column names, table names, or SQL fragments from clients.

Trust frontend-supplied identifiers for security boundaries.

5. Security & Secrets (P0)
MUST

Application startup MUST FAIL FAST if required secrets are missing or invalid.

JWT keys MUST meet minimum strength requirements.

All secrets MUST be injected via environment or secret managers.

MUST NOT

Commit secrets to Git (current or historical).

Log tokens, passwords, or PII.

6. Performance & Safety (P1)
MUST

Reporting queries MUST run under a read-only DB role.

Reporting connections MUST enforce:

statement_timeout ≤ 30s


Heavy or slow operations MUST be offloaded to background jobs.

MUST NOT

Allow reporting workloads to starve transactional connections.

7. Naming & Style (P2)
MUST

Use snake_case for DB and API fields.

Use NUMERIC(20,4) for money.

New code MUST follow the current formatting and lint rules.

MAY

Legacy code may remain unchanged unless modified.
