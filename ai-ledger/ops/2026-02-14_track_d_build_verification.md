## 2. Issues Encountered & Fixes Applied

### Issue 1: Poetry Version Mismatch
- **Symptom**: `poetry.lock` generated by Poetry 2.2.1, Dockerfile installed Poetry 1.8.4
- **Error**: `pyproject.toml changed significantly since poetry.lock was last generated`
- **Fix**: `backend/Dockerfile` line 25 — `poetry==1.8.4` → `poetry==2.2.1`

### Issue 2: China Network Throttling (apt + PyPI)
- **Symptom**: `apt-get update` and `pip install` hanging/failing behind firewall
- **Fix**: Added Aliyun mirrors for all three package sources:
  - apt: `sed -i 's/deb.debian.org/mirrors.aliyun.com/g'`
  - pip: `-i https://mirrors.aliyun.com/pypi/simple/`
  - Poetry: `ENV POETRY_PYPI_MIRROR_URL=https://mirrors.aliyun.com/pypi/simple/`

### Issue 3: PostgreSQL Password Mismatch
- **Symptom**: `asyncpg.exceptions.InvalidPasswordError: password authentication failed for user "mpango"`
- **Cause**: Postgres volume persisted old password from previous `docker compose up`
- **Fix**: `docker compose down -v` to destroy stale volume, re-init with current `.env` password

### Issue 4: REPORTING_USER_PASSWORD Missing
- **Symptom**: `RuntimeError: REPORTING_USER_PASSWORD environment variable must be set`
- **Cause**: Migration `011_s6_p_reporting_role.py` requires this env var at module import time
- **Fix**: Added `REPORTING_USER_PASSWORD` to `docker-compose.yml` backend environment

### Issue 5: Alembic Version Column Too Short
- **Symptom**: `StringDataRightTruncationError: value too long for type character varying(32)`
- **Cause**: Revision IDs like `003_phase_b3_orders_minimal_closed_loop` (43 chars) exceed default VARCHAR(32)
- **Fix**: `database/init.sql` pre-creates `alembic_version` table with `VARCHAR(128)`

### Issue 6: init.sql Conflicts with Alembic
- **Symptom**: `DuplicateTableError: relation "wholesalers" already exists`
- **Cause**: `init.sql` created `wholesalers` table, then Alembic migration 001 tried to create it again
- **Fix**: Removed table/index/data creation from `init.sql` — Alembic owns the schema

### Issue 7: Multi-Tenant Migration Architecture
- **Symptom**: `UndefinedTableError: relation "users" does not exist`
- **Cause**: Migration 001 only creates `users` table in tenant schema context (`-x tenant_schema=t_xxx`). Migration 007 creates indexes on `users` without checking schema context. Running `upgrade head` without `-x` only creates public tables.
- **Fix**: Disabled automatic migrations in `docker-entrypoint.sh`. Migrations must be run manually in two steps (public + tenant).

### Issue 8: CORS_ORIGINS Parse Error
- **Symptom**: `SettingsError: error parsing value for field "CORS_ORIGINS"`
- **Cause**: JSON brackets `["..."]` in `.env` get mangled by Docker Compose YAML interpolation
- **Fix**: Removed `CORS_ORIGINS` from compose environment and `.env`. Pydantic-settings uses its Python default.

### Issue 9: DATABASE_URL Validator Rejection
- **Symptom**: `ValueError: DATABASE_URL must start with 'postgresql://' or 'postgres://'`
- **Cause**: Compose default used `postgresql+asyncpg://` but `core/config.py` validator rejects driver suffix
- **Fix**: Changed to `postgresql://` in both `.env` and `docker-compose.yml`

## 4. Known Limitations

1. **Migrations are manual** — Multi-tenant architecture requires `alembic upgrade head` (public) + `alembic upgrade head -x tenant_schema=t_dev` (tenant) as separate steps.
2. **Aliyun mirrors hardcoded** — For non-China deployments, remove mirror lines from Dockerfile.
3. **No init_staging.sh yet** — Referenced in deployment guide but not created. Manual `docker compose up -d` works.
