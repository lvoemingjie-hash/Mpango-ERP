## 三、详细分析

### GAP 1: 📊 报表与数据看板 (Reporting & Dashboard)

**当前状态**: PRD 中无任何报表/分析模块的功能描述。库存预警看板 (特性 4.3) 有简要提及，但无系统性的 BI/Dashboard 规划。

**缺失内容**:
- 销售报表（日/周/月营收、销量排行、订单趋势）
- 客户绩效报表（Top 客户、活跃度、下单频率）
- 库存周转报表
- 批发商仪表盘 KPI（总销售额、待处理订单、低库存商品数、应收账款）
- 报表导出（PDF/Excel）

**影响**: 批发商无法通过系统进行数据驱动的决策。

**建议**: 在 MVP 阶段至少提供一个基础 Dashboard + 核心销售/库存报表。

> **备注**: 后端 Phase 6 (S6) 已完成 BI Foundation、Read Models、Dashboard API 等技术实现。PRD 需补充产品层面的需求定义，与已有技术产出对齐。

---

### GAP 2: 💰 财务/发票/收据 (Finance / Invoicing)

**当前状态**: PRD 仅在阶段划分中提及 "Phase 2: 财务对账、赊销账期"，无任何 MVP 阶段的财务功能描述。

**缺失内容**:
- 收入追踪（批发商如何查看总收入）
- 利润率计算（采购价 vs 售价）
- 税务处理（增值税 / 预扣税 — 非洲市场关键需求）
- 发票/收据生成（可打印的订单发票）
- M-Pesa 支付对账
- 退货信用证/借记单处理

**影响**: 批发商无法完成基本的财务管理，依赖外部工具，系统价值大打折扣。

**建议**: MVP 阶段至少实现：订单发票自动生成 + 基础收支汇总 + M-Pesa 交易对账。

---

### GAP 3: 🔄 退货与退款管理 (Returns & Refunds)

**当前状态**: PRD 完全没有退货/退款流程的描述。

**缺失内容**:
- 退货申请流程（零售商发起 → 批发商审核 → 退货确认）
- 退货原因分类（损坏、错发、质量问题）
- 退货后库存回补逻辑
- 各支付方式的退款流程（M-Pesa、COD、赊销）
- 部分退货/换货支持

**影响**: 真实业务中退货是高频场景，缺少此流程将导致批发商使用线下方式处理，数据断裂。

**建议**: MVP 阶段实现简化版退货流程（至少支持整单退货 + 库存回补）。

### GAP 5: ⚠️ 异常处理与边界情况 (Error Handling & Edge Cases)

**当前状态**: PRD 中几乎没有异常场景的描述。

**缺失内容**:
- M-Pesa 支付超时或失败的处理流程
- 商品在购物车中被删除或下架的处理
- 批发商停用/注销后，零售商待处理订单的处理
- 并发下单冲突（两个零售商同时下单，库存仅剩1件）
- 网络中断时的数据一致性保证

**影响**: 开发团队在实现时将面临大量"PRD 没说怎么办"的困惑，可能导致不一致的实现。

**建议**: 针对每个核心流程补充至少 3-5 个异常场景及处理规则。
