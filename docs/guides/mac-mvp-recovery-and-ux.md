## 客户遇到响应不明时

普通下单、替换草稿和付款申报会在第一次写入之前，把原操作标识及完整请求保存在当前浏览器标签页。保存和回读验证失败时不发送。恢复记录包含业务报价、金额字符串、方式、参考号等，不包含本次功能新增的登录凭据保存；既有 authStore 的凭据机制未在本授权中修改。

刷新、离开页面后在同一标签页返回原操作入口，可主动恢复原请求。恢复不会自动发起；未知结果时不能修改原请求或静默换标识。原订单报价仍由服务器判断，价格变更必须重新明确同意。替换恢复会保留原旧草稿 ID，不因旧草稿已取消而改成另一笔新单。

付款申报恢复使用原始金额字符串、方式和参考号。只有明确的输入拒绝允许用户选择“编辑拒绝输入并新建”；超时、冲突、认证或权限失败都不会自动变成新申报。历史币种未核实的已保留操作可以交给当前认证下的后端严格重放判断，新申报则必须先核实币种；转账参考号不能为空白。

记录按当前账号、租户 ID/schema、供应商门户及操作/订单隔离。当前 DTO 不保留独立 retailer binding ID；后端继续按 token user/tenant 解析有效客户绑定、检查订单归属。浏览器记录不是授权来源。换账号/租户/门户不会恢复另一上下文的操作，失效会话和撤权必须经当前服务拒绝；旧账号迟到成功不能跳转当前账号。

确认成功后清理对应记录并进入订单。若本地清理失败但服务端成功已核实，显示明确成功入口，不让客户再次点击提交。不要清除网站数据、换浏览器或开新标签页重填未知操作；关闭标签页、设备损坏、存储清理后的恢复不由 sessionStorage 保证，必须由商户核对服务器结果。本轮不新增服务端操作查询系统。

## 收款人员

Codex-L 2026-10-30 有限接入替代本节旧print/invoice准备合同：先点 Review payment，读取同一申报的 `/declarations/{id}/review-context`。payments:read即可核对，不再额外要求orders:read；只读人员可看但不能确认，只有确认权限也不能据此读取。当前READY、当前payments:confirm_declaration及人工勾选已核实到账三者齐备，才沿用原单次确认POST。客户/供应商、申报/订单、active binding与当前账号/租户必须一致；缺字段、读取拒绝、未知币种、失效或切换均清旧核对及勾选。

确认沿用单次原接口。收据入口 ID 仅取成功响应 data.id；缺失时显示“确认成功但收据链接不可用”，绝不回退请求 ID 或之前收据 ID。

余额和申报金额直接展示新GET的精确十进制字符串及订单快照币种，不再调用invoice/print作为核对或精度回退。已知零有效展示但不是确认许可；null明确未核实而非零。名称按name_resolution，不屏蔽真实同名Supplier/Retailer，也不以登录个人名补商业名称。observed_at只是读取观察点，不是余额锁或到账证明；UNRESOLVED/NOT_ACTIONABLE不开放确认。失败后重读并重新勾选，不自动重发写入。打印继续独立存在，历史NULL币种的严格同key/body恢复不以新GET成功为前置。

## 已有页面呈现

- 首页各区块独立加载、提示权限/网络错误及重试，成功内容不被另一接口错误遮住。开店步骤及岗位快捷入口只指向已有路由，并按现有权限展示；不伪造待办数量或步骤完成度。
- 商品查询变更回第一页，旧结果/错误不能覆盖新查询。空目录与无搜索结果分别说明，可清除和重试。主价格对应可下单的具体包装及其币种，各包装展示价格和可下单状态，不称“最低价”。
- 客户页通过独立非财务GET `/client/auth/context` 展示当前双方商业主体、active binding和观察时点，个人登录名另列；缓存门户代码仅为路由提示。拒绝/失联时清旧名称并局部提示刷新，不阻断原client子路由或严格恢复，不从商户核对GET取名。没有新增供应商切换功能。
- 订单、付款、履约分别解释；申报不是到账凭证，订单状态不等于付款状态。准确“部分到账/待付款”仍需要权威金额/状态字段，不从合并状态推断。
- 付款与读取失败提供安全用户文案。部分旧报价控件名称和历史币种技术标签受既有断言覆盖，保留原合同并在文档解释；统一全站用语待单独审定。
- 库存拒绝必须填写原因；未知拒绝结果重试保留原原因和原标识。技术版本信息收进详情，数量正负有说明。
- 关闭弹窗和退出图标有可访问名称，表单 label 关联，当前导航标明 aria-current。实际小屏/键盘运行证据以交付包为准，不能用 jsdom 宣称像素或焦点验收。
