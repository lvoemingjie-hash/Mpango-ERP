## Root Cause Details

## Issue 1: Frontend container unhealthy due to Compose healthcheck mismatch

### Evidence
`frontend/Dockerfile` defines the correct runtime healthcheck:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD wget -qO- http://127.0.0.1:80/ || exit 1
```

But the effective Compose healthcheck is:

```json
["CMD","wget","-qO-","http://localhost:80/"]
```

And `docker compose config` confirms this override under `frontend.healthcheck.test`.

### Runtime proof inside container
**Command**:
```sh
wget -qO- http://127.0.0.1:80/ >/dev/null && echo ok-127 || echo fail-127
wget -qO- http://localhost:80/ >/dev/null && echo ok-localhost || echo fail-localhost
```

**Result**:
```text
ok-127
wget: can't connect to remote host: Connection refused
fail-localhost
```

### Impact
- Frontend service is functionally serving traffic.
- Container health is falsely reported as failed.
- This can break automation that waits for all services to become healthy.
