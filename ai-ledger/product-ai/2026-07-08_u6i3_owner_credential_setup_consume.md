## Scope

U6-I3 adds backend service logic to consume an owner credential setup token and prepare owner/admin credential setup inputs for the next slice.

Included:

- New `OwnerCredentialSetupService.consume_setup_token(raw_token, password)` service method.
- Hash-only token lookup using `owner_credential_setup_tokens.token_hash`.
- Token validity checks for purpose, expiry, used, revoked, and soft-delete state.
- Success path marks the token `used_at=now`.
- Success path returns `registration_id`, `tenant_schema`, `owner_email`, and a bcrypt `password_hash` generated by `core.security.hash_password`.
- Tests proving no endpoint, query-string support, raw token persistence, registration password persistence, or tenant user/admin/RBAC creation.

Excluded:

- No migration.
- No API endpoint.
- No frontend.
- No `User`, `Role`, `Permission`, admin, or RBAC creation.
- No `TenantProvisioningService` behavior change.
- No raw token storage or logging.
- No query-string token support.

## Token Boundary Decisions

- Raw setup tokens are stripped, hashed with the existing HMAC token hashing helper, and never persisted.
- Invalid, missing, expired, used, revoked, deleted, and wrong-purpose tokens fail through the same neutral `OwnerCredentialSetupTokenInvalidError` message.
- U6-I3 does not write the generated `password_hash` to `TenantRegistration`; it returns the hash for the future admin-creation slice.
- The only persisted state change on success is `OwnerCredentialSetupToken.used_at`.
