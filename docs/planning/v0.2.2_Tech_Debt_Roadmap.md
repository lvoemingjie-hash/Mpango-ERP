## 1. Direct Response to CTO Review

### 1.1 Middleware Ordering: RBAC Before Validation (Critical)

You are correct. This is a semantic consistency violation.

**What happens today:**

```
Request
  → Starlette BaseHTTPMiddleware (AuthenticationMiddleware)
    → attaches auth_ctx + tenant_ctx to request.state
      → FastAPI Dependency Injection
        → RequirePermission.__call__() → reads request.state → 403
          → Pydantic model parsing → 422 (never reached)
            → Route handler
```

A user who sends `POST /api/v1/orders` with `{"items": []}` (invalid payload) gets a **403 Forbidden** instead of a **422 Validation Error**. From the client's perspective, they cannot distinguish "I lack permission" from "my payload is malformed" — this breaks the contract that 4xx codes are semantically distinct.

**Why FastAPI makes this tricky:**

FastAPI's dependency injection model evaluates `Depends()` callables in declaration order, **before** Pydantic parses the request body. This is by design — FastAPI assumes auth should gate access before the framework spends cycles parsing/validating untrusted input. The rationale is security-first: don't parse attacker payloads for unauthenticated requests.

However, our architecture already authenticates at the middleware layer (`AuthenticationMiddleware`). The `RequirePermission` dependency is a **second** auth gate that runs in DI-space, creating a double-gate where the inner gate (RBAC) blocks validation.

The core tension:

| Concern | Wants to run first | Reason |
|---------|-------------------|--------|
| **Security** | Auth + RBAC | Don't parse untrusted payloads |
| **UX/API Semantics** | Validation | Give clients actionable 422 errors |

Our middleware already solves the security concern (unauthenticated requests are rejected at the ASGI layer). The DI-level `RequirePermission` is therefore a **authorization refinement**, not a security gate — and it should yield to validation.

### 1.2 OpenAPI Drift (High)

You are correct. We do not currently have a canonical `docs/contracts/openapi.yaml` that matches our actual route surface. The test suite references this file but it does not exist. This means:

1. **SDK generation will fail** — any `openapi-generator` run will produce stale or empty output.
2. **Security annotations are missing** — protected routes don't declare their `securitySchemes` in the generated OpenAPI spec, so generated clients won't know to attach Bearer tokens.
3. **Contract-first development is broken** — we cannot diff "spec vs implementation" because there is no frozen spec.

## 2. Root Cause Analysis

### 2.1 RBAC Ordering — Architectural Diagram

```
┌─────────────────────────────────────────────────────┐
│                   ASGI Stack                         │
│                                                      │
│  ┌─ RequestLoggingMiddleware ─────────────────────┐  │
│  │  ┌─ PrometheusMetricsMiddleware ─────────────┐ │  │
│  │  │  ┌─ CORSMiddleware ────────────────────┐  │ │  │
│  │  │  │  ┌─ AuthenticationMiddleware ─────┐  │  │ │  │
│  │  │  │  │  ✓ JWT decode                  │  │  │ │  │
│  │  │  │  │  ✓ Tenant context resolution   │  │  │ │  │
│  │  │  │  │  ✓ request.state.auth_ctx set  │  │  │ │  │
│  │  │  │  │                                │  │  │ │  │
│  │  │  │  │  ┌─ FastAPI Router ──────────┐ │  │  │ │  │
│  │  │  │  │  │                           │ │  │  │ │  │
│  │  │  │  │  │  1. Depends(RequirePerm)  │ │  │  │ │  │  ← 403 HERE
│  │  │  │  │  │  2. Pydantic body parse   │ │  │  │ │  │  ← 422 never reached
│  │  │  │  │  │  3. Route handler         │ │  │  │ │  │
│  │  │  │  │  └───────────────────────────┘ │  │  │ │  │
│  │  │  │  └────────────────────────────────┘  │  │ │  │
│  │  │  └──────────────────────────────────────┘  │ │  │
│  │  └────────────────────────────────────────────┘ │  │
│  └─────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────┘
```

The problem is structural: `Depends()` callables execute in the **dependency resolution phase**, which precedes the **body parsing phase** in FastAPI's request lifecycle.

### 2.2 OpenAPI Drift — Why It Happened

We built routes incrementally across Tracks S1–S7 without regenerating or freezing the OpenAPI spec after each track. The `docs/contracts/openapi.yaml` referenced in early tests was a design-phase artifact that was never kept in sync with implementation.

## 3. Actionable Roadmap for v0.2.2

### 3.1 TD-1: Refactor Auth/RBAC to Run After Pydantic Validation

**Priority:** P0 — Blocks API semantic consistency
**Effort:** 3–5 days
**Risk:** Medium (touches every protected endpoint)

#### Approach: Custom `APIRoute` with Validation-First Semantics

FastAPI supports custom `Route` classes via `APIRouter(route_class=...)`. This is the cleanest solution because it lets us control the exact execution order without fighting the framework.

**Target execution order:**

```
1. Starlette Middleware    → AuthenticationMiddleware (JWT decode, tenant resolve)
2. Pydantic body parsing   → 422 if invalid                    ← MOVED UP
3. RBAC permission check   → 403 if unauthorized               ← MOVED DOWN
4. Route handler           → business logic
```

**Implementation plan:**

| Step | Description | Files |
|------|-------------|-------|
| TD-1.1 | Create `api/routing.py` with `ValidatedRoute(APIRoute)` that overrides `get_route_handler()` to parse+validate the request body before running auth dependencies | `api/routing.py` (new) |
| TD-1.2 | Split `RequirePermission` into two layers: (a) a lightweight `Depends()` that only extracts `TokenPayload` from `request.state` (no permission check), and (b) a post-validation permission gate inside the custom route handler | `api/middleware/rbac.py` |
| TD-1.3 | Migrate all `APIRouter` instances to use `route_class=ValidatedRoute` | `api/v1/*.py` |
| TD-1.4 | Add integration tests: send invalid payload to protected endpoint → assert 422, not 403 | `tests/test_request_validation.py` |
| TD-1.5 | Remove all `xfail` markers from `test_request_validation.py` | `tests/test_request_validation.py` |

**Alternative considered and rejected:**

- **Exception handler approach** (`@app.exception_handler(RequestValidationError)`): This doesn't solve the ordering problem — if RBAC raises 403 before body parsing, `RequestValidationError` is never raised. The exception handler only fires if validation actually runs.
- **Moving RBAC into middleware**: This would require the middleware to know which permission each route requires, coupling middleware to route definitions. Violates separation of concerns.

**Validation criteria:**

```python
# This MUST return 422, not 403:
response = client.post("/api/v1/orders", json={"items": []})
assert response.status_code == 422

# This MUST still return 403 for valid payload + wrong permissions:
response = client.post("/api/v1/orders", json=valid_order_payload)
assert response.status_code == 403
```

### 3.2 TD-2: Fix OpenAPI Spec Generation for Protected Routes

**Priority:** P1 — Blocks SDK generation
**Effort:** 2 days
**Risk:** Low

**Implementation plan:**

| Step | Description | Files |
|------|-------------|-------|
| TD-2.1 | Add global `securitySchemes` to FastAPI app via `app = FastAPI(... swagger_ui_init_oauth=..., components={"securitySchemes": {...}})` | `main.py` |
| TD-2.2 | Annotate all protected routers with `dependencies=[Depends(jwt_bearer)]` at the router level, so OpenAPI auto-generates `security: [{"bearerAuth": []}]` on every protected operation | `api/v1/*.py` |
| TD-2.3 | Add a CI step: `python -c "from main import app; import json; print(json.dumps(app.openapi()))" > docs/contracts/openapi.json` to freeze the spec on every merge to `main` | `Makefile` or `scripts/freeze_openapi.py` (new) |
| TD-2.4 | Generate `docs/contracts/openapi.yaml` from the frozen JSON (single source of truth is the FastAPI app, YAML is a derived artifact) | CI pipeline |
| TD-2.5 | Update `test_route_coverage.py` to validate against `app.openapi()` (live introspection) instead of a static YAML file | `tests/test_route_coverage.py` |
| TD-2.6 | Remove all `skip` markers from `test_route_coverage.py` | `tests/test_route_coverage.py` |

**Design decision:** The FastAPI app is the **source of truth** for the API contract. The YAML file is a **derived artifact** generated in CI. This eliminates spec drift by construction.
