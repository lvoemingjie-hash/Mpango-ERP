### F-05（BLOCKER，根因二）：忘记密码流程静默失效

**已确证事实**：三次 UI 提交均返回中性成功，`password_reset_tokens` 恒为 0；应用外重放同一服务代码（同库同 env）`issued=True` 可提交——即应用内存在使 token 不发行的路径，且无任何异常日志。
**根因假设（待源码因果验证）**：应用内租户会话上下文（RLS/GUC）可能使 wholesalers 扫描在应用会话内返回空；中性 200 策略进一步在外部完全掩盖故障。真实用户将永远等不到重置邮件且无任何错误线索。

### F-13（BLOCKER，根因一·用户症状，旅程终止点）：邀请获客入口经导航不可达

症状：真实批发商经任何受支持导航均无法进入邀请获客流程。表层观察：`InvitePage` 存在但为孤儿页面（侧栏 `Sidebar.tsx:32-38` 无此项，Customers 页无邀请按钮），操作者全程未找到入口。根因与修复项见第二部分 F-14（同一根因的诊断证据）。

### F-09（HIGH_FRICTION，财务正确性）：国家不联动货币

注册国家 UG（乌干达），财务模块货币 KES（肯尼亚先令）。国家→默认货币映射缺失；未来需支持例外结算货币（如 USD）。将直接影响未走到的 Step 8/11/12（定价、付款申报、财务记录）。

完整发现清单（F-01..F-14）见 `2026-08-21_dc12r1_mvp_l1_j1_h1_friction_findings.csv`；逐步事件含时间戳/耗时/客观证据见 `2026-08-21_dc12r1_mvp_l1_j1_h1_journey_events.csv`。

## CTO 已裁定的修复范围控制（转录 + E1 约束）

- **根因一 MVP 必修（一个修复项，覆盖 F-13/F-14）**：新建**批发商侧邀请创建流程入口**（侧栏或 Customers 页清晰 "Invite retailer" 入口 + 空态 CTA + 导航测试），打通"创建邀请 → 获得链接/码"的生产端。**E1 明确约束：不得将公共消费页 `/invite/:code` 直接挂到批发商侧栏**——该页是零售商凭码消费端，语义与鉴权均不适用于批发商侧。
- **二维码邀请**：高价值增强，不替代最小入口修复；实施前需单独定义 token 生命周期、防重放、批发商绑定、过期与泄漏合同。
- F-05 修复须先完成源码级因果验证（确认/否证 RLS/GUC 假设），并同时解决"中性 200 策略掩盖内部故障"的可观测性问题（内部应告警/日志，外部保持中性）。
