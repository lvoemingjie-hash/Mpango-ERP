## Issue A — Login Endpoint Contract Violation

### Root Cause

During Track H-Fix-01, `backend/api/v1/auth.py` was rewritten locally to implement two-phase auth (identity JWT → tenant selection). However, this file was **never staged or committed** in the v0.2.1-rc1 tag.

The v0.2.1-rc1 commit `69ecf32` included:
- ✅ `schemas/auth.py` — `LoginRequest` with only `email` + `password`
- ✅ `crud/user.py` — `find_user_across_tenants()` function
- ❌ `api/v1/auth.py` — **OLD** code still referencing `request.tenant_code`

### Fix

Committed the correct `backend/api/v1/auth.py` (+222, -97 lines). Key changes:

| Before (rc1 — old code) | After (rc2 — correct code) |
|---|---|
| `get_wholesaler_by_code(db, request.tenant_code)` | `find_user_across_tenants(db, request.email, request.password)` |
| Returns `LoginResponse` with contextual JWT | Returns `IdentityLoginResponse` with identity JWT + `available_tenants[]` |
| Single-phase login | Two-phase: `/login` → identity, `/select-tenant` → contextual |

### Login Flow (rc2)

```
POST /auth/login {email, password}
  → find_user_across_tenants() scans all active tenant schemas
  → verify password
  → return Identity JWT + available_tenants[]

POST /auth/select-tenant {tenant_id}  (requires Identity JWT)
  → verify user access to tenant
  → return Contextual JWT scoped to tenant
```

## Issue B — Migration 016 Enum Dependency

### Root Cause

Migration `016_add_returned_status` ran `ALTER TYPE order_status ADD VALUE IF NOT EXISTS 'returned'` but the enum did not exist in the public schema of the staging DB.

OPS emergency-patched with `__import__('sqlalchemy').text()` — functional but poor code quality.

### Fix

Clean rewrite with proper imports and idempotent logic:

```python
from alembic import op
from sqlalchemy import text

def upgrade() -> None:
    conn = op.get_bind()
    result = conn.execute(
        text("SELECT 1 FROM pg_type WHERE typname = 'order_status'")
    ).fetchone()

    if result is None:
        op.execute(text(
            "CREATE TYPE order_status AS ENUM "
            "('pending', 'confirmed', 'processing', 'shipped', "
            "'delivered', 'cancelled', 'returned')"
        ))
    else:
        op.execute(text(
            "ALTER TYPE order_status ADD VALUE IF NOT EXISTS 'returned'"
        ))
```

Safe for: empty DB, existing DB with enum, re-runs.

## Governance Lesson

**This incident was not a code bug — it was a commit workflow failure.**

The `git add` in the v0.2.1-rc1 workflow explicitly listed individual files but missed `backend/api/v1/auth.py`. The schema and CRUD were committed, but the endpoint that consumes them was not.

**New rule:** Before tagging any RC, run `git diff --cached --stat` to verify all modified files are staged.
