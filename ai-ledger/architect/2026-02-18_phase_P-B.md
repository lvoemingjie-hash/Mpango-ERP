## 1. Architecture Decisions

### 1.1 Notification Service: Stub with Provider-Agnostic Interface

**Decision:** Create `services/notification_service.py` with `send_email()` and `send_sms()` that log to files instead of calling external providers.

**Justification:**
- Real SMS/email providers (Twilio, SendGrid, Africa's Talking) require paid API keys and external infrastructure.
- A stub implementation gives the same code path so that when providers are integrated, only the transport layer changes — no business logic rewiring needed.
- Dedicated log files (`logs/email.log`, `logs/sms.log`) provide auditable evidence of what *would* be sent.

**Design:**
```
NotificationService (singleton)
├── send_email(to, subject, body) → logs to email.log + console
└── send_sms(phone, message) → logs to sms.log + console
```

### 1.2 Notification Hook: Fire-and-Forget in OrderService.transition

**Decision:** Hook notifications into `OrderService.transition()` with full try/except — notifications never block the atomic order transition.

**Justification:**
- The CRUD layer (`crud/order.py`) is the direct path used by API routes, but `OrderService.transition` is the canonical state machine with ledger posting.
- Adding notifications here means any caller using the proper transition path automatically gets notifications.
- Fire-and-forget pattern: if the notification fails (e.g., log write error), the order transition still succeeds — commerce > comms.

**Trigger rules:**
| Target State | Action |
|---|---|
| `CONFIRMED` | Send **email**: "Order #{short_id} Confirmed" |
| `FULFILLED` | Send **SMS**: "Order #{short_id} is on the way!" |

### 1.3 Streaming CSV: Generator + StreamingResponse

**Decision:** Use Python async generators with FastAPI `StreamingResponse` instead of in-memory buffer.

**Justification:**
- Kenyan wholesalers may have tens of thousands of orders. Loading all rows into a single string would consume proportional RAM.
- `StreamingResponse` + generator keeps memory constant: each batch of 500 rows is fetched, serialised to CSV rows, and yielded to the HTTP response stream.
- Batch size of 500 rows balances DB round-trips vs. memory pressure.

**Endpoint architecture:**
```
GET /api/v1/orders/export?format=csv      → orders_export_{timestamp}.csv
GET /api/v1/inventory/export?format=csv   → inventory_export_{timestamp}.csv
```

### 1.4 Separate Router from Async Exports

**Decision:** Create `api/v1/data_export.py` (streaming, synchronous) separate from `api/v1/exports.py` (async job-based).

**Justification:**
- `exports.py` uses the S4 job queue for heavy analytics reports — returns a job_id, polls for completion.
- `data_export.py` streams simple tabular dumps directly in the HTTP response — no job queue, no polling.
- Different use cases, different architectures. Keeping them in separate files avoids muddling the two patterns.

## 4. Export Endpoint Specification

### GET /api/v1/orders/export?format=csv

| Parameter | Type | Description |
|---|---|---|
| `format` | query | Must be `csv` (400 otherwise) |
| `status` | query | Optional filter (e.g. `confirmed`, `paid`) |

**CSV Columns:**
| Column | Source |
|---|---|
| Order ID | `order.id` |
| Status | `order.status.value` |
| Total Amount (KES) | `order.total_amount` |
| Retailer ID | `order.retailer_id` |
| Notes | `order.notes` (newlines replaced with spaces) |
| Item Count | `len(order.items)` |
| Created At | `order.created_at` (ISO 8601) |
| Updated At | `order.updated_at` (ISO 8601) |

### GET /api/v1/inventory/export?format=csv

**CSV Columns:**
| Column | Source |
|---|---|
| Stock ID | `stock.id` |
| SKU Code | `sku.sku_code` |
| SKU Name | `sku.name` |
| Category | `sku.category` |
| Unit | `sku.unit` |
| Quantity On Hand | `stock.quantity_on_hand` |
| Quantity Reserved | `stock.quantity_reserved` |
| Available | `on_hand - reserved` |
| Is Active | `sku.is_active` |
| Last Updated | `stock.updated_at` |

### Streaming Implementation
```python
async def _generate() -> AsyncGenerator[str, None]:
    yield _csv_row(HEADER)  # Header
    offset = 0
    while True:
        rows = await db.execute(stmt.offset(offset).limit(500))
        if not rows: break
        for row in rows:
            yield _csv_row([...])  # One row at a time
        offset += 500
```

**Memory profile:** O(batch_size) regardless of total row count.
