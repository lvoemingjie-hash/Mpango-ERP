EVIDENCE NORMALIZATION AUDIT — MPANGO_TENANT_BOOTSTRAP_DB_AUTHORITY_R1_R3
============================================================================

WHY THIS FILE EXISTS
--------------------
The harness writes its evidence as plain text/JSON. The repository's NORMAL
pre-commit hooks (`trailing-whitespace`, `end-of-file-fixer`) rewrote those
generated files at commit time. No hook was bypassed (no --no-verify), no
evidence file was hand-edited, and no evidence content was rewritten by hand.
This audit records, with facts recomputable from this repository, that the
change is semantic-free.

WHAT CHANGED, EXACTLY
---------------------
1. The generated files already used CRLF line endings (Python text-mode writes on
   Windows). Git stores them as LF blobs — its own text normalization when
   staging. This is the ordinary working-tree-vs-blob pair the R-series manifests
   record for source files as well.
2. `end-of-file-fixer` appended ONE end-of-file newline. For the machine report
   this is provable: its as-generated digest was recorded at first validation,
   before any git command ran —
       harness_report.json as-generated = 2a6a7344e5e202a8068c88c5c1e105a0a484753efef7aa7b47b1e69b3371d78d
   — and removing the committed working-tree file's single final newline byte
   reproduces that digest exactly (verified here: True). Proof that the
   added byte is a bare LF and nothing else: the stored blob equals the
   working-tree bytes with every CRLF replaced by LF (verified for every file in
   the table below: True); and CRLF-converting the blob back reproduces the
   working-tree bytes except for that one final byte.
3. Trailing whitespace inside the captured logs was stripped (see SCOPE below).

REPORT SEMANTICS UNCHANGED
--------------------------
The committed report is identical to the generated report after JSON parsing, and
the post-normalization report was re-validated against the R1-R3 identity gate:
task and authorization are R1-R3, verdict PASS, eight mutations all RED, MM8 7/7
named REDs, synthetic-secret scan 0 of 19.

CROSS-CONSISTENCY OF THE COMMITTED EVIDENCE — 28/28 PASS
--------------------------------------------------------
- every suite run's reported rc equals the `rc=` header of its committed log
  (6/6 suites, all rc=0);
- every mutation's reported FAILED nodeids, and every declared named-RED nodeid,
  appear as `FAILED <nodeid>` in that mutation's committed log (MM1-MM8, including
  MM8's 7/7);
- the committed verify logs carry rc=0 (intact database) and rc=2
  (runtime-owned-guard counterexample);
- the report's pre-run and restored script digests equal the current working-tree
  bytes of both scripts, and those bytes are LF-normalized identical to the
  committed blobs of implementation candidate a21878c1 — i.e. every mutation
  restore returned the scripts to exactly the candidate bytes.

SCOPE OF THE NORMALIZATION
--------------------------
Removals are limited to trailing whitespace on a line, including whitespace-only
lines (pytest `--tb=short` padding: "E     " -> "E", "  " -> ""), plus the single
end-of-file newline described above. No line was added, removed or reordered
otherwise, and no assertion, count, digest, identity field, verdict or secret-scan
result changed.
